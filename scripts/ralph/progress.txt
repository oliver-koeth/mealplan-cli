# Ralph Progress Log
## Codebase Patterns
- Calendar persistence uses `JsonCalendarStore` with a JSON object root keyed by canonical `YYYYMMDD`; missing entries should raise deterministic `DomainRuleError` (`calendar.<date>: meal plan not found`) instead of returning `None`.
- CLI calendar persistence should resolve storage from `MEALPLAN_CALENDAR_STORE_PATH` when set and otherwise use `~/.mealplan/calendar.json` so saves are stable across working directories and easily isolated in tests.
- CLI calendar retrieval should parse persisted payloads via `parse_contract(MealPlanResponse, payload)` before rendering with shared `_render_output(...)` so `calendar` and `calculate` stay format-consistent (`json|text|table`).
- UI calendar API routes should parse `/api/v1/calendar/{date}` path segments, normalize dates to canonical `YYYYMMDD` before store access, and map missing-date `DomainRuleError` to HTTP `404` with canonical `calendar_not_found` error envelope details.
- Calculate page defaults should reuse settings-storage keys (`activity_level`, `training_load_tomorrow`, `training_before_meal`) and only backfill from `mealplan.ui.settings.v1` when no day-specific value exists in `mealplan.ui.calculate.v1`.
- In `ui_server.py` `_APP_SHELL_TEMPLATE`, escape literal JavaScript regex end anchors as `$$` (not `$`) so `string.Template` placeholder substitution does not crash HTML rendering.
- In `ui_server.py`, when adding a new top-level page, update `_PAGE_CONTENT`, `do_GET` route dispatch, and `_render_app_shell` active-nav substitutions together so navigation and routing stay in sync.
